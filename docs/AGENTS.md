責務分離とファイル分割の方針:

- 1つのファイルに複数の抽象レベルを混在させないこと
- orchestration、mapping、utility はできるだけ別ファイルに分けること
- 特に repository 系ファイルは「保存順や transaction 制御」と「DTO/DB row の変換 helper」を同居させすぎないこと
- package 直下にファイルを増やすときは、まず「read」「save」「mapper」など役割単位で分けること
- 安易に `foo_helper.go` のような名前を増やさず、責務が分かる名前を使うこと
- ある package 配下でファイルが増えても、同じドメイン責務なら直下に置いてよい
- ただし read/write/mapping/test utility まで混ざって見通しが悪くなるなら、まずファイル分割で整理すること
- 下位 package を切るのは最後の手段にすること
- 新しい実装を足す前に、既存ファイルがその責務を持つべきかを判断し、責務が広がりすぎるなら先に分割すること
- Step 完了時はコード変更だけでなく、対応する `docs/*.md` の進捗や実装メモも更新すること
